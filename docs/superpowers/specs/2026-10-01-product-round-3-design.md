## Часть A. Исследование по странам: налог для удалёнщика, банки, виза кочевника

Три новых источника правды по 69 странам, собранные агентами-исследователями по брифу, как обзоры легализации. Все три — обзоры в Markdown с короткой фиксированной структурой; числа для выборок извлекаются из обзоров скриптом, чтобы текст и число не расходились.

### Обзоры

Папка `data/notes/<factorId>/<countryId>.md`, шапка как у легализации (`countryId`, `checkedAt`, `sources` ≥ 2). Структура разделов задаётся на фактор в коде, `shared/lib/notes/specs.ts`:

| Фактор              | Разделы                                                            | Строка со значением в последнем разделе                                                                             |
| ------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `legalization-ease` | Въезд · Пути к ВНЖ · ПМЖ и гражданство · Подводные камни · Вердикт | `Оценка: N из 5`                                                                                                    |
| `remote-tax`        | Режим для удалёнщика · Расчёт на 60 000 $ в год · Вердикт          | `Ставка: N %` (эффективная, одна десятая допустима)                                                                 |
| `banking-ease`      | Счёт в банке · Карты и переводы · Вердикт                          | `Оценка: N из 5`                                                                                                    |
| `nomad-visa`        | Условия · Вердикт                                                  | `Виза: есть` или `Виза: нет`; при «есть» ещё `Минимальный доход: N $ в месяц` или `Минимальный доход: не требуется` |

`parseNote(raw, spec)` принимает описание разделов и регулярку значения; старый вызов без spec означает легализацию. Тест данных проверяет каждую папку по её spec.

### Рубрика для `banking-ease`

5 — счёт открывают по загранпаспорту без ВНЖ, карты работают, SWIFT и переводы из России доступны (Казахстан, Армения, Кыргызстан). 4 — счёт по ВНЖ или с небольшими условиями, ограничения точечные (Грузия, Турция, Сербия, Таиланд). 3 — счёт реально только с ВНЖ или через необанки, переводы из России затруднены (ОАЭ, Испания, Черногория). 2 — банки массово отказывают россиянам, счёт только с ВНЖ и после комплаенса, переводы из России почти невозможны (Германия, Нидерланды, Чехия). 1 — счета закрывают или не открывают, карты не выпускают (Польша, Прибалтика).

### Сбор

Бриф `docs/collect-research.md` обобщает `collect-legalization.md`: один агент — пять стран, три обзора на страну, ветка `notes/research-<n>`. После всех пачек один агент калибрует оценки банков по рубрике и генерирует три выборки скриптом `scripts/collect/notes-to-samples.ts` (универсальный: фактор → spec → выборка).

### Интерфейс

Блок обзора в карточке становится общим: `FactorNote` по конфигу `[{ factorId, title }]`; в карточке три блока: «Легализация», «Налоги для удалёнщика», «Банки». Виза кочевника показывается строкой в «Справке» с минимальным доходом.

## Часть B. Стоимость жизни в долларах и режим бюджета

- Выборка `cost-of-living.numbeo-usd-2026`: «estimated monthly costs for a single person without rent» со страниц городов Numbeo, USD. Скрипт `scripts/collect/cost-of-living-usd.ts`, одна страница на город с паузой 1,5 с и кэшем; формат фактора меняется на `usd-per-month` «≈ $1 000 в месяц без аренды», определение и подсказка обновляются; индексная выборка остаётся неактивной.
- **Режим бюджета.** Поле «Мой доход в месяц, $» в панели настроек (хранится в ссылке как `b=2500`). Когда задано, у каждого города в списке и в карточке показывается «Останется ≈ $800» = доход − стоимость жизни − аренда, с тоном: ≥ 30 % дохода good, ≥ 10 % ok, иначе bad; города, где остаётся меньше нуля, помечаются «не по карману» и уходят вниз списка, но не скрываются. В `RankingState` поле `budget: number | null`, в `RankedCityView` поле `leftover: number | null`. Сортировка по баллу не меняется, только пометка; опционально переключатель «Сначала по карману».

## Часть C. Таблица с сортировкой и квиз

- **Таблица.** Третья вкладка панели «Таблица» (на десктопе — вкладка слева, таблица раскрывается на всю ширину вместо карты; на телефоне — экран с горизонтальным скроллом). Колонки: город, страна, балл и все числовые факторы с данными; ячейки — значение и фон по тону уровня; клик по заголовку сортирует по возрастанию/убыванию, повторный клик меняет направление; сортировка хранится в ссылке `sort=rent:asc`. Выбор колонок не делаем, их 20.
- **Квиз.** На `/start` кнопка «Не знаю, кто я — пройти опрос» ведёт на `/quiz`: пять вопросов с вариантами, каждый вариант добавляет веса или фильтры; в конце квиз выбирает ближайшую персону по сумме весов и дополняет её ответами, переходит на `/#p=<id>&w=…&f=…`. Вопросы: срок (на пару месяцев / на год-два / насовсем), доход (удалённый из России / удалённый из-за рубежа / буду искать работу на месте), климат (тёплая зима важна / без разницы / не люблю жару), важнее всего (дёшево / безопасно / быстро легализоваться / поближе к России), размер города (мегаполис / средний / небольшой → фильтр `population`). Логика — чистая функция `quizToSettings(answers)` с тестами.

### Как собрать экономно

Старый `cities.ts` искал Q-id по координатам и ходил в источники; это и заняло часы. Для расширения — новый `scripts/collect/cities-extend.ts`:

1. Список из кода, по 50 названий за один запрос `wbgetentities&sites=enwiki&titles=…` → Q-id, русский лейбл, координаты, страна. Четыре запроса, секунды.
2. `--limit 5` на отладку, полный прогон один раз, кэш ответов на диске.
3. Пишет только добавленные записи в `cities.json` и `countries.json` (слияние с существующими, без пересборки).
4. Пересбор факторов: все скрипты сбора идемпотентны и читают список городов из файла; оркестратор запускает их по очереди с кэшем, сетевые — только для новых ключей. Новые страны получают обзоры легализации, налогов и банков теми же брифами, батчами по пять.
