# Продуктовый раунд 2 — дизайн

Oct 1, 2026 · @Игорь, Claude

По итогам исследования конкурентов (Nomad List, Numbeo, Expatistan, Teleport, InterNations, livingcost, passport.help и русскоязычные гайды). Ниша «взвешенный выбор города для россиянина» пустая; конкуренты дают три вещи, которых у нас нет: осмысленные персоны вместо ползунков, ссылку с настройками для шаринга и сравнение городов. Плюс факторы, о которых просят чаще всего: прямые рейсы из России, размер города, аренда в долларах, духота.

Три пул-реквеста в `develop`, в конце релиз.

## Часть 1. Персоны, панель настроек, ссылка

### Пресеты-персоны

Два выпадающих списка «Срок» и «Доход» заменяются одним рядом карточек-персон. Пресет в `presets.json` получает описание и ярлыки, поле `kind` уходит:

```json
{
  "id": "remote-long",
  "name": "Удалёнщик надолго",
  "description": "Жить за границей на визе кочевника или простом ВНЖ, зарплата из России или из-за рубежа.",
  "highlights": ["дёшево", "легко легализоваться", "хороший интернет"],
  "weights": { ... }, "enabled": { ... }, "ranges": { ... }, "filters": { ... }
}
```

Шесть персон, веса и фильтры поверх базовых настроек реестра:

Фильтр `entry-visa ≠ refused` записывается как `allowed` со всеми категориями, кроме `refused`. `work-visa` в фильтрах не используется, у него нет данных.

Персона по умолчанию при первом заходе — `remote-long`. Карточка персоны: название, описание, ярлыки, активная выделена. На телефоне ряд листается горизонтально. Под рядом строка состояния: «Свой вариант · изменено 3 фактора · Сбросить» появляется, как только пользователь отходит от персоны; «Сбросить» возвращает персону.

В `RankingState`: `presetId: string | null`, `changedFactorIds` (факторы, чьи вес, галочка, диапазон или фильтр отличаются от персоны), `resetToPreset()`.

### Панель настроек

- В заголовке группы счётчик «Климат · 2 из 3» и две кнопки-ссылки «все» / «ни один», которые включают или выключают галочки факторов с данными в группе.
- У каждого ползунка рядом с весом доля в итоговом балле: «9 · 24 %». Доля = вес / сумма весов включённых факторов.
- Точка-маркер у фактора, который отличается от персоны.
- Над списком городов поле поиска по названию города и страны, фильтрует список без пересчёта ранжирования, ранг сохраняется. Пустой результат: «Ничего не найдено».
- Под списком чип «Скрыто фильтрами: 41 · Сбросить фильтры», если фильтры отсекают хотя бы один город. Пустая выдача: «Фильтры отсекли все города. Самый строгий: Безопасность от 50» и кнопка сброса. Самый строгий — фильтр, который отсекает больше всего городов в одиночку.

### Ссылка с настройками

Состояние хранится в хеше адреса, только отличия от «база + персона», чтобы ссылка была короткой:

```
#p=remote-long&w=rent:9,safety:3&off=it-salary&on=time-to-citizenship&r=winter-temp:10-24&f=entry-visa:visa-free|e-visa;safety:60-&c=tbilisi
```

- `p` — персона; `w` — веса, отличные от персоны; `on`/`off` — галочки; `r` — диапазоны; `f` — фильтры (`min-max`, любой край пустой; категории через `|`); `c` — открытый город.
- Чистая функция `serializeState` / `parseState` в `entities/ranking/lib/url-state.ts` с тестами: круговой обход, мусор в хеше игнорируется, неизвестные факторы отбрасываются.
- Чтение при создании состояния; запись через `replaceState` в `$effect` с комментарием (синхронизация с адресной строкой — внешний мир). Запись не чаще раза в 300 мс.
- Кнопка «Поделиться» в шапке панели: копирует адрес, показывает «Скопировано».

## Часть 2. Новые факторы и аренда в долларах

Четыре сборщика по `docs/collect.md`, ветка `data/round-2`.

| ---------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `population`     | Население города, чел.                                      | Wikidata P1082, последнее значение, по Q-id из `scripts/collect/cities.ts` (переиспользовать резолвер)                                                                                                                                                                                                         | новый формат `population`: «1,2 млн»; `range`, диапазон по умолчанию [300 000, 5 000 000], `defaultEnabled: false`; ярлыки «подходящий размер / слишком маленький / слишком большой»; шкала без тона: <300 тыс «маленький», <1 млн «средний», <5 млн «большой», ≥5 млн «мегаполис» |

## Часть 3. Сравнение городов

- В `RankingState`: `compareIds: CityId[]` до трёх, `toggleCompare(id)`, `clearCompare()`; сохраняется в ссылке как `cmp=tbilisi|belgrade`.
- В карточке города и в строке списка кнопка «Сравнить» (иконка весов); в списке — только по наведению или как маленькая кнопка справа от бейджа.
- Плашка над списком «Сравнить: Тбилиси, Белград · Открыть · Очистить», появляется при одном и более выбранных.
- Экран сравнения — `Sheet` во всю ширину на десктопе и во весь экран на телефоне: таблица, строки — факторы в порядке реестра, колонки — города; в ячейке значение в человеческом формате и метка уровня; первая колонка липкая, на телефоне горизонтальный скролл. Сверху балл, ранг и сводка каждого города. Категориальные факторы — словами. Кнопка «Убрать» у колонки.
- Новые слайсы: `features/compare-toggle`, `widgets/compare-sheet`.

## Тесты

- Vitest: url-state круговой обход и мусор; `changedFactorIds` и `resetToPreset`; «самый строгий фильтр»; форматы `population` и `usd-per-month`; компаратор до трёх городов.
- Playwright: выбор персоны меняет первый город; поле поиска находит город; ссылка с `#p=family` открывает персону «Семья с детьми»; сравнение двух городов показывает таблицу с двумя колонками.
