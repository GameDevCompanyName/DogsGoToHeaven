# Читаемые метрики и цвет — дизайн

Oct 1, 2026 · @Игорь, Claude

Ответ на фидбэк после первого использования: метрики не интерпретируются, интерфейс серый и мелкий, непонятно, почему город в топе. Опирается на `2026-09-28-mvp-ui-design.md`.

## Договорённости

1. **Каждое значение показывается по-человечески**: формат, понятный без знания источника («на 39 % дешевле Нью-Йорка», «≈ $4 800 в месяц до налогов»), плюс словесный уровень («безопасно», «чисто по норме ВОЗ»).
2. **Уровни бывают абсолютные и относительные, и это видно.** Где есть общепринятая шкала (ВОЗ, EF, Numbeo, FCC), уровень абсолютный и подписан ею. Где нет, уровень относительный и звучит как «дешевле, чем в 80 % городов», а не «хорошо».
3. **Цвет всегда с текстом.** Зелёный, жёлтый, красный дублируются словом, чтобы читалось без цвета.
4. **Пороги, подписи, подсказки и короткие ярлыки — данные в реестре факторов**, код только форматирует.
5. **«Почему город в топе» — сильные и слабые стороны по вкладу с учётом весов пользователя.** Фактор с нулевым весом сильной стороной не бывает.
6. **Деньги в долларах**, потому что источники в долларах. Тёмной темы нет. Ползунки и пресеты не меняются.

## Реестр: поле `presentation`

У каждого фактора появляется обязательное поле:

```json
"presentation": {
  "format": "nyc-index",
  "hint": "Индекс Numbeo: цены на еду, транспорт и услуги без аренды; Нью-Йорк = 100, меньше — дешевле.",
  "chip": { "good": "дёшево", "bad": "дорого" },
  "bands": { "type": "percentile" }
}
```

- `format` — один из именованных форматов ниже. Код знает, как отрисовать каждый.
- `hint` — одно-два предложения: что это за число, откуда, как понимать. Показывается по тапу на название фактора.
- `chip` — короткие ярлыки для списка городов и сводки в карточке. У категориальных факторов ярлыков нет.
- `bands` — либо `{ "type": "percentile" }`, либо абсолютная шкала:

```json
"bands": {
  "type": "absolute",
  "source": "https://www.who.int/publications/i/item/9789240034228",
  "sourceName": "норма ВОЗ",
  "levels": [
    { "max": 5, "label": "чисто", "tone": "good" },
    { "max": 10, "label": "хорошо", "tone": "good" },
    { "max": 15, "label": "умеренно", "tone": "ok" },
    { "max": 25, "label": "загрязнено", "tone": "bad" },
    { "label": "сильно загрязнено", "tone": "bad" }
  ]
}
```

Уровни идут по возрастанию значения, `max` включительно, у последнего `max` нет. `tone` — `good`, `ok`, `bad`. Для факторов «меньше лучше» первые уровни хорошие, для «больше лучше» — последние; направление задано в `scoring`, шкала просто перечисляет уровни по значению.

### Форматы значений

| `format`        | Факторы                                   | Что показываем                                               |
| --------------- | ----------------------------------------- | ------------------------------------------------------------ |

| `relative-only` | sunshine                                  | число не показываем, только относительный уровень            |

Температурные факторы — `range`: тон уровня зависит от диапазона пользователя, а не от шкалы. Тон: внутри диапазона `good`, до 3 °C за границей `ok`, дальше `bad`; текст «в вашем диапазоне» или «теплее диапазона на 4 °C».

Ярлыки `chip` для числовых факторов: стоимость жизни «дёшево / дорого», аренда «дешёвая аренда / дорогая аренда», зарплата «высокие зарплаты / низкие зарплаты», налоги «низкие налоги / высокие налоги», безопасность «безопасно / небезопасно», здравоохранение «хорошая медицина / слабая медицина», воздух «чистый воздух / грязный воздух», зима «мягкая зима / холодная зима», лето «комфортное лето / жаркое лето» (для `range` в «плохом» ярлыке подставляется «холодное лето», если ниже диапазона), солнце «солнечно / пасмурно», гражданство «быстро до гражданства / долго до гражданства», легализация «легко легализоваться / сложно легализоваться», английский «хороший английский / слабый английский», интернет «быстрый интернет / медленный интернет», время «удобный часовой пояс / неудобный часовой пояс».

## Относительный уровень

Для каждого числового фактора и города считается доля городов, у которых значение хуже с учётом направления: `betterThanShare = worse / (withData − 1)`, при одном городе — 1. Для `range` относительный уровень не считается, там текст про диапазон. Считается один раз в `entities/city` из датасета (значения не зависят от настроек), кэшируется по фактору.

Тон относительного уровня: ≥ 0.66 `good`, ≥ 0.33 `ok`, ниже `bad`. Текст берётся из шаблона в `bands`: `{ "type": "percentile", "phrase": "дешевле, чем в {n} % городов" }`, где `{n}` — округлённая доля.

## Сильные и слабые стороны

В `RankingState` у `RankedCityView` появляются:

- `percentile` — перцентиль ранга среди показанных городов (сейчас считается в карте, переезжает сюда, карта берёт отсюда);
- `strengths` — до трёх факторов: активные, `normalized ≥ 0.66`, отсортированы по вкладу, первые три;
- `weaknesses` — до двух факторов: активные, `normalized ≤ 0.33`, отсортированы по доле веса, первые два.

Список городов: под страной строка ярлыков: зелёные из `strengths`, красные из `weaknesses`, через точку, не больше четырёх суммарно. Ярлык — `chip.good` или `chip.bad` фактора.

Карточка: под заголовком фраза-сводка: «В топе за счёт: дёшево, безвиз, тёплая зима. Минус: слабый английский». Если сильных сторон нет: «Ровный профиль без явных плюсов». Разбор балла делится на три группы с заголовками: «Тянет вверх» (normalized ≥ 0.66), «Тянет вниз» (≤ 0.33), «Остальное». В каждой строке: название фактора с кнопкой подсказки, цветная метка уровня с текстом, значение в человеческом формате, относительная или абсолютная подпись, источник. Полоска вклада остаётся и красится в тон.

## Цвет и размер

- Тон → цвет в одном месте, `shared/lib/tone`: `good` зелёный, `ok` янтарный, `bad` красный, `neutral` серый. Классы для фона метки, текста и полоски. Контраст текста на фоне не ниже 4.5:1.
- Бейдж балла: фон по перцентилю ранга в пять ступеней той же палитры, число тёмное. В карточке и в списке.
- Базовый размер шрифта 16px на телефоне и десктопе (сейчас 14–15 в большинстве мест). Название города и балл — `text-base`/`text-lg`, вторичный текст — `text-sm` цветом `foreground` с прозрачностью 70 %, а не `muted-foreground`.
- Подсказка фактора: `Popover` из shadcn-svelte по тапу на значок ⓘ рядом с названием; внутри `hint`, для абсолютных шкал строка «Шкала: <sourceName>» со ссылкой.

## Слои

- `shared/lib/ranking/schemas.ts` — схема `presentation` (обязательное поле), типы `Presentation`, `Bands`, `Tone`. Валидация: у `absolute` уровни по возрастанию `max`, у `percentile` есть `phrase`, у категориальных `chip` отсутствует. Движок содержимое не использует.
- `shared/lib/tone` — тип `Tone` и классы.
- `entities/city/lib`: `format-value.ts` расширяется форматами; новый `interpret.ts`: `interpretValue(factor, value, dataset, range?) → { text, level: { label, tone, kind: 'absolute' | 'relative' | 'range' } | null }`; `percentile.ts`. Всё с тестами.
- `entities/city/ui`: `ScoreBadge` цветной, `LevelChip`, `FactorHint`.
- `entities/ranking`: `strengths`, `weaknesses`, `percentile` во view. Тесты.
- `widgets/results-list`: ярлыки. `widgets/city-card`: сводка, группы, метки. `widgets/city-map`: перцентиль из view.
- `data/factors.json`: `presentation` для всех 18 факторов. `docs/data.md`: раздел про `presentation`.

## Тесты

- Vitest: форматы (каждый формат по одному примеру), `interpretValue` для абсолютной шкалы на границе, для перцентиля, для `range` внутри и снаружи; сильные и слабые стороны с учётом весов (фактор с нулевым весом не попадает); схема отклоняет уровни не по порядку.
- Playwright: у первого города в списке есть хотя бы один ярлык; в карточке есть заголовок «Тянет вверх» и метка уровня с текстом.
