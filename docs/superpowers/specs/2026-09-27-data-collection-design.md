# Сбор датасета — дизайн

Закрывает пункт 3 роадмапа из `docs/prd.md`. Опирается на модель данных из `2026-09-27-data-model-and-ranking-design.md`.

## Договорённости

1. **Города — только за пределами России.** Единственный критерий отбора. Список собирается как объединение трёх списков кандидатов примерно по сто: качество жизни, популярность у переезжающих из РФ, мировая популярность. Дубли схлопываются, итоговое число не фиксировано.
2. **Оценки модели не используются нигде.** Значение либо взято из источника, либо его нет. Фактор без проверяемого источника остаётся без `activeSample`.
3. **Определения факторов выбираются по доступности данных:** одной таблицей на весь мир или расчётом из координат. Ради этого зарплата в IT и скорость интернета переходят на уровень страны, воздух измеряется как PM2.5 «меньше лучше», а «срок до ВНЖ» становится «сроком до гражданства».
4. **Порог готовности города — 60 % и задаётся в коде.** Город виден в выдаче, если у него есть значения не менее чем по 60 % факторов с активной выборкой. Константа, а не данные, чтобы менять осознанно и с тестами.
5. **Единица работы сборщика — один фактор.** Один агент, одна ветка, один скрипт, один файл выборки. Данные проходят через скрипт в файл, а не через контекст агента.

## Реестр факторов

У каждого фактора появляется обязательное поле `definition`: что измеряем, в каких единицах, как трактовать пограничные случаи. Сборщик измеряет ровно это.

| id                    | Определение                                          | Уровень | Направление  |
| --------------------- | ---------------------------------------------------- | ------- | ------------ |

| `rent`                | Индекс аренды, Нью-Йорк = 100                        | город   | меньше лучше |
| `it-salary`           | Медианная годовая компенсация разработчика, USD      | страна  | больше лучше |

| `safety`              | Индекс безопасности 0–100                            | город   | больше лучше |
| `healthcare`          | Индекс доступности и качества здравоохранения 0–100  | страна  | больше лучше |
| `air-quality`         | Среднегодовая концентрация PM2.5, мкг/м³             | город   | меньше лучше |

## Порог покрытия в движке

- `DatasetCity` получает поле `coverage: number` (0–1): доля факторов с активной выборкой, по которым у города есть значение. Если ни у одного фактора нет активной выборки, `coverage = 0`.
- Константа `MIN_CITY_COVERAGE = 0.6` экспортируется из `shared/lib/ranking`.
- `rank(dataset, settings, options?)` принимает `options.minCoverage`, по умолчанию константа. Города ниже порога попадают в `excluded` с `reason: 'coverage'` и пустым `failedFilterIds`. Проваленные фильтры — `reason: 'filter'`. Проверка покрытия идёт до фильтров.
- Нормализация по-прежнему считается по всем городам датасета.

## Отчёт о покрытии

`npm run data:report` (скрипт `scripts/data-report.ts` через `tsx`) читает `data/` напрямую с диска, прогоняет схемы и `validateRawData`, печатает таблицу: фактор, активная выборка, покрытие в процентах по городам; внизу — сколько городов проходят порог из общего числа. Возвращает ненулевой код, если данные невалидны.

## Список городов

Отдельный агент до всех сборщиков. Собирает три списка кандидатов скриптом `scripts/collect/cities.ts` из открытых источников, объединяет, исключает Россию, берёт координаты и страну из Wikidata или GeoNames, пишет `data/cities.json` и `data/countries.json`. Русские названия — из Wikidata (label `ru`). Результат валидируется владельцем глазами до запуска сборщиков факторов.

## Инструкция сборщика

`docs/collect.md` — самодостаточный бриф для агента с одним фактором. Правила:

1. Читать только `definition` фактора, список городов или стран и эту инструкцию.
2. Искать источник, где значения есть для многих городов или стран сразу. Значения, которых нет в источнике, не заполнять.
3. Скачивание и парсинг — в `scripts/collect/<factorId>.ts`. Скрипт пишет `data/samples/<factorId>.<source>-<year>.json`, включая маппинг названий источника на наши id. Скрипт остаётся в репозитории для обновления.
4. Файл выборки в контекст не читать: только `head`, `wc -c`, `npm run data:report`, `npm run test`.
5. Прописать `activeSample`, закоммитить на ветку `data/<factorId>`, вернуть отчёт: источник, покрытие, что не удалось.
6. Уважать условия источников: не обходить защиту, не долбить сервер, предпочитать скачиваемые таблицы.

## Оркестрация

Оркестратор (сессия Claude Code) запускает субагентов по одному на фактор, каждого в своём worktree. Отчёты короткие, контекст оркестратора не растёт. Ветки сливаются в `data/initial-dataset`, `npm run verify`, один пул-реквест с таблицей покрытия.
