# Данные: формат и порядок сбора

Sep 27, 2026 · @Игорь, Claude

Справочник по формату файлов. Пошаговый бриф для агента-сборщика — `docs/collect.md`. Данные лежат в папке `data/` в корне репозитория, отдельно от кода. Формат и решения по нему описаны в `docs/superpowers/specs/2026-09-27-data-model-and-ranking-design.md`, здесь — практика.

## Файлы

```
data/
  factors.json      реестр групп и факторов
  presets.json      пресеты срока и режимы дохода
  countries.json    страны
  cities.json       города
  samples/          выборки: одна выборка — один файл
```

Правила для всех файлов:

- Идентификаторы — `kebab-case` латиницей: `chiang-mai`, `cost-of-living`.
- Страны — ISO 3166-1 alpha-2 в нижнем регистре: `ge`, `th`.
- Даты — `YYYY-MM-DD`.
- Русские названия — в полях `name`.
- Пропуск данных — отсутствие ключа или `null`. Не выдумывать значения.

## Как добавить выборку

Выборка — одно измерение одного фактора из одного источника. Файл `data/samples/<factorId>.<suffix>.json`, где `suffix` описывает источник и год: `cost-of-living.numbeo-2026.json`.

```json
{
  "id": "cost-of-living.numbeo-2026",
  "factorId": "cost-of-living",
  "source": {
    "name": "Numbeo Cost of Living Index",
    "url": "https://www.numbeo.com/cost-of-living/",
    "period": "2026 mid-year",
    "collectedAt": "2026-09-27",
    "notes": "Индекс относительно Нью-Йорка = 100"
  },
  "unit": "индекс",
  "values": { "tbilisi": 38.2, "berlin": 71.5 }
}
```

- `id` совпадает с именем файла без `.json` и начинается с `factorId`.
- `period` — к какому времени относятся данные, свободный текст. `collectedAt` — когда мы их собрали.
- `unit` — подпись единицы для карточки города. У категориальных факторов не нужен.
- `source.url` — полный адрес с протоколом, если есть.
- Для факторов «меньше лучше» вроде разницы во времени с Москвой значение — модуль, без знака.
- Ключи `values` — id городов для факторов с `level: city` и id стран для `level: country`. Смотри `level` в `factors.json`.
- Значения: числа для числовых факторов, коды категорий из `factors.json` для категориальных.

По одному фактору может лежать несколько выборок. Движок использует только ту, что указана в `activeSample` фактора в `factors.json`. Собрав выборку, пропиши её id в `activeSample`, если она должна стать рабочей. Старые выборки не удаляй: они остаются как альтернативные источники.

## Как добавить город или страну

В `cities.json`:

```json
{ "id": "tbilisi", "name": "Тбилиси", "countryId": "ge", "lat": 41.69, "lon": 44.83 }
```

Страна города должна быть в `countries.json`: `{ "id": "ge", "name": "Грузия" }`.

## Как добавить фактор

В `factors.json`, в массив `factors`. Порядок в файле — порядок показа в интерфейсе.

Числовой фактор участвует в ранжировании:

```json
{
  "id": "sunshine",
  "kind": "numeric",
  "name": "Солнечные дни",
  "definition": "Часов солнечного сияния в год",
  "group": "climate",
  "level": "city",
  "scoring": { "type": "higher-better" },
  "defaultWeight": 4,
  "defaultEnabled": true
}
```

`definition` обязательно: что измеряем и в каких единицах, сборщик измеряет ровно это. `scoring.type` — `higher-better`, `lower-better` или `range` с `defaultRange: [низ, верх]`. `defaultWeight` — целое 0–10.

Категориальный фактор — только фильтр, в балл не входит:

```json
{
  "id": "nomad-visa",
  "kind": "categorical",
  "name": "Виза цифрового кочевника",
  "definition": "Есть ли действующая виза цифрового кочевника, доступная гражданам РФ",
  "group": "legalization",
  "level": "country",
  "categories": [
    { "code": "yes", "name": "Есть" },
    { "code": "no", "name": "Нет" }
  ]
}
```

Новая группа — в массив `groups` того же файла. Код приложения при добавлении фактора не меняется.

## Обзоры к значениям факторов

Папка `data/notes/<factorId>/<key>.md` хранит текстовые обзоры к значению фактора: ключ — id города или страны по уровню фактора. Сейчас так хранятся обзоры легализации для граждан РФ: `data/notes/legalization-ease/<countryId>.md`. Формат файла, структура разделов и рубрика оценки описаны в `docs/collect-legalization.md`. Интерфейс подгружает обзор по требованию, в бандл целиком он не попадает. Тест данных проверяет шапку, порядок разделов, число источников и строку «Оценка: N из 5».

## Проверка

Перед коммитом:

```bash
npm run data:report
npm run test
```

`data:report` печатает покрытие по факторам и число городов, проходящих порог `MIN_CITY_COVERAGE` (60 %, константа в движке): город с меньшей долей заполненных факторов в выдаче не показывается.

Тест `src/shared/api/dataset/data.test.ts` прогоняет всю папку `data/` через схемы и проверяет связи: существование городов, стран, факторов и выборок, коды категорий, имена файлов. Схемы строгие: неизвестный ключ, в том числе опечатка в необязательном поле, — ошибка. Ошибки связей называют файл и ключ; ошибки схемы указывают путь вида `samples[2].values.tbilisi`, где индекс — порядок файлов в `samples/` по алфавиту. Пока тест красный, задача не готова.

## Что не решено

- Пресеты — стартовые догадки. Их веса и фильтры правятся в `presets.json` без кода.
- Визовые данные для РФ меняются часто: у таких выборок особенно важны `period` и `collectedAt`, а в интерфейсе они показываются с дисклеймером.
