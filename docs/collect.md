# Бриф сборщика данных

Sep 27, 2026 · @Игорь, Claude

Самодостаточная инструкция для агента, который собирает **одну выборку по одному фактору**. Прочитай её целиком, потом `definition` своего фактора в `data/factors.json`, и больше ничего читать не нужно. Формат файлов подробно описан в `docs/data.md`.

## Главные правила

1. **Только источник.** Значение либо взято из источника, либо его нет. Никаких оценок «по памяти», округлений «примерно» и заполнения пропусков соседями. Пустой ключ лучше выдуманного числа.
2. **Данные не проходят через контекст.** Ты пишешь скрипт, скрипт пишет файл. Файл выборки ты не открываешь целиком. Смотришь только `head -c 600`, `wc -c`, `npm run data:report` и `npm run test`.
3. **Один фактор, одна ветка, один файл.** Не трогай чужие выборки, чужие скрипты и `cities.json`. В `factors.json` меняешь только `activeSample` своего фактора.
4. **Уважай источник.** Не обходи защиту от ботов, не долби сервер: одна страница-таблица лучше трёхсот страниц по городу. Если источник запрещает автоматическую выгрузку, ищи другой или скачиваемый файл.

## Шаги

1. Создай ветку `data/<factorId>` от `main`.
2. Найди `definition`, `level` и `kind` своего фактора в `data/factors.json`. Для `level: city` ключи выборки — id из `data/cities.json`, для `level: country` — id из `data/countries.json`. Список id получай скриптом, а не чтением файла: `node -e "console.log(require('./data/cities.json').map(c=>c.id).join(' '))"`.
3. Найди источник, где значения есть сразу для большинства городов или стран: годовой отчёт, индекс с таблицей, открытый API, скачиваемый CSV. Открытые API без ключа предпочтительнее скрейпинга. Записывай источник: название, адрес, к какому периоду относятся данные.
4. Напиши `scripts/collect/<factorId>.ts`. Скрипт:
   - скачивает источник (или читает файл, положенный рядом в `scripts/collect/raw/`, если источник — ручная выгрузка; тогда опиши в комментарии, откуда файл);
   - сопоставляет названия источника с нашими id; таблицу соответствий держи в скрипте, сомнительные совпадения не сопоставляй;
   - пишет `data/samples/<factorId>.<source>-<year>.json` в формате из `docs/data.md`, для числовых факторов — числа, для категориальных — коды из `categories`;
   - печатает в конце: сколько ключей заполнено из скольких и первые десять ненайденных.
     Запуск: `npx tsx scripts/collect/<factorId>.ts`.
5. Проверь: `npm run data:report` показывает покрытие твоего фактора, `npm run test` зелёный. Если не зелёный, чини по сообщению: оно называет файл и ключ.
6. Если покрытие достойное (ориентир — не меньше половины ключей), пропиши id выборки в `activeSample` своего фактора. Если нет, выборку всё равно закоммить, но `activeSample` не трогай и напиши об этом в отчёте.
7. `npm run verify`, коммит `data(<factorId>): add <source> sample`, пуш ветки. Пул-реквест не открывай, это сделает оркестратор.
8. Верни отчёт из четырёх строк: источник и период; покрытие в процентах; что не удалось сопоставить и почему; проставлен ли `activeSample`.

## Подсказки по источникам

Это подсказки, не предписание. Если источник недоступен или нарушает условия, ищи замену с тем же смыслом.

| Фактор                                   | Где обычно есть                                                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `cost-of-living`, `rent`, `safety`       | Numbeo, страницы рейтингов по индексу: одна таблица на все города                                                              |
| `it-salary`                              | Stack Overflow Developer Survey, медиана по странам                                                                            |
| `tax-burden`                             | Wikipedia «List of countries by tax rates»                                                                                     |
| `healthcare`                             | IHME Healthcare Access and Quality Index, Numbeo Health Care Index                                                             |
| `air-quality`                            | IQAir World Air Quality Report, WHO Ambient Air Quality Database                                                               |
| `winter-temp`, `summer-temp`, `sunshine` | Open-Meteo Climate / Archive API по координатам из `cities.json`, без ключа                                                    |
| `entry-visa`                             | Wikipedia «Visa requirements for Russian citizens»                                                                             |
| `nomad-visa`                             | Wikipedia «Digital nomad visa», списки стран с такими визами                                                                   |
| `time-to-citizenship`                    | Wikipedia, статьи о натурализации по странам, таблицы сроков проживания                                                        |
| `english`                                | EF English Proficiency Index                                                                                                   |
| `internet-speed`                         | Speedtest Global Index                                                                                                         |

## Бриф для списка городов

Отдельная задача до всех факторов. Скрипт `scripts/collect/cities.ts`:

1. Собирает три списка кандидатов примерно по сто городов: качество жизни (Numbeo Quality of Life, Mercer), популярность у переезжающих из РФ (данные о направлениях эмиграции 2022–2025, профильные рейтинги), мировая популярность (Euromonitor Top City Destinations, Nomad List).
2. Объединяет без дублей. Города России исключает, это единственный критерий отбора. Итоговое число не фиксировано.
3. Для каждого города берёт из Wikidata: русское название, страну (ISO alpha-2), координаты. Для каждой страны — русское название.
4. Пишет `data/cities.json` и `data/countries.json`. `id` города — латинский slug из английского названия: `chiang-mai`, `sao-paulo`.
5. Печатает число городов и стран и города, для которых Wikidata ничего не нашла.

Ветка `data/cities`, отчёт: сколько городов, сколько стран, что не удалось.
