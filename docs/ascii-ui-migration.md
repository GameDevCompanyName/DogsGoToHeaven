# Миграция на Svelte ASCII UI: результат и обратная связь

Пакет: `svelte-ascii-ui@0.1.0`, Svelte `5.57.3`. Исходная документация проверена в установленном пакете: README, `docs/agents/using.md`, `feedback.md`, `docs/components.md`, `docs/design-system.md`; недостающие сигнатуры уточнялись по публичным типам. Дата: 8 ноября 2026.

## Что заменено

Удалены shadcn-svelte, Bits UI, Lucide, старые скопированные примитивы, конфигурация shadcn, tw-animate-css, tailwind-variants и прежняя палитра. Приложение использует Theme Phosphor и публичные компоненты пакета. Tailwind отвечает за раскладку, MapLibre — за карту, нативные таблицы — за специфичные таблицы данных. Это границы ответственности из consumer guide, а не оставленная вторая дизайн-система.

Кнопки, ссылки, формы, галочки, ползунки, числовые поля, карточки пресетов, панели, подсказки, модальные окна, индикаторы и обзоры используют новый пакет. Данные и формула рейтинга не менялись. Географическая карта получает цвета из публичной `palettes.phosphor`.

Для чтения русских таблиц выбран IBM Plex Mono через публичный `Theme.font`. DotGothic16 проверен первым: на том же экране 1366×900 текст занимал существенно больше места, подписи мобильной навигации дробились. Это наблюдение о пригодности для плотного интерфейса, не утверждение об ошибке шрифта. Примеры до/после сохранялись локально; итоговые кадры используют IBM Plex Mono.

## Чего не хватило в гайдах

1. **Рецепта для Tailwind Preflight.** Reset обнуляет стандартный margin у dialog, поэтому обычный Dialog появляется у края. Исправлено поддерживаемым `class="m-auto"` на корне Dialog. Не применялись внутренние селекторы, CSS-патчи или копии компонентов. Полезен пример установки рядом с Tailwind с проверкой положения модального окна.
2. **Примера плотного кириллического интерфейса.** Настройка `font` описана, но нет примера с длинными русскими названиями и таблицами на 390px. Добавить пример Paper + альтернативный моноширинный шрифт и явно напомнить проверять переносы.
3. **Компоновки навигации на всю высоту.** Tabs хорошо работает со своим `panel` snippet. Без него нет связей tab → tabpanel; не стоит использовать такой режим для отдельно расположенных областей без пояснения семантики. Здесь используем навигацию из Button и сохраняем области смонтированными, чтобы поиск и прокрутка не сбрасывались.
4. **Списка переводимых строк.** У Dialog/Drawer и NumberInput английские close/increment/decrement labels по умолчанию. Все использованные подписи переведены через props. Короткий checklist локализации был бы полезнее поиска каждого prop в исходниках.
5. **Примера нормализации NumberInput.** Когда приложение восстанавливает обязательную границу после очистки, нужно обновить `bind:value`, а не только DOM value; иначе следующая кнопка шага использует пустое внутреннее значение. Это ошибка первой версии нашей интеграции, исправленная привязкой и регрессионным сценарием, а не подтверждённый дефект библиотеки.

## Каких возможностей не хватило

- Drawer с открытием снизу и более гибкая ширина/высота окна. Теперь карточка справа занимает 67vw на широком десктопе и 50vw на небольшом; на телефоне используется центрированный Dialog вместо прежнего нижнего Sheet. Содержимое и действия доступны, но точная визуальная эквивалентность не достигнута.
- Вариант Badge с контуром для относительной оценки и заливкой для абсолютной. Текст уровня и пояснение шкалы сохранены; прежнее различие оформлением отсутствует.
- Для крупных числовых оценок хотелось бы отдельный пример: Badge s компактен и предназначен для меток, а не акцентного балла. Для числа используется прикладная композиция: крупный балл /100 и семантический фон; текстовые уровни остаются штатными Badge m.

Таблицы и resizable panes прямо исключены из текущего каталога: это не неожиданная поломка. Для этой миграции хватило прикладных таблиц; контроллер изменения ширины не добавлялся.

Подробные локальные черновики с публичными воспроизведениями: [ограничения overlays и Badge](ascii-ui-feedback-overlays.md). Запрос списка issues через GitHub REST вернул пустой список. Issues не публиковались: feedback workflow требует одобрения конкретного полного текста и места публикации.

## Проверка и ограничения

Проверяются готовые, пустые и disabled состояния, смена персоны/веса, фильтры, бюджет, сортировка, сравнение, ссылки и открытия/закрытия карточки. Отдельно проверена очистка числового диапазона с последующими кнопками ±. Скриншоты: 1366×900 и 390×844, без горизонтального переполнения документа; физический телефон и скринридер не проверялись.

В автоматизированном браузере внешний слой карты не отрисовался; это отмечено отдельно и не выдаётся за проверенную карту. Контейнер карты и остальные сценарии проверены. `npm run verify` завершился успешно: Prettier, ESLint, Steiger, svelte-check (0 errors / 0 warnings), 263 Vitest-теста и 26 Playwright-сценариев. В песочнице Windows потребовалось отдельно завершить собственный preview после тестов: сценарии уже прошли, остановка дочернего Vite была заблокирована окружением. Svelte MCP autofixer применён к изменённым компонентам; замечания о существующих эффектах URL/MapLibre проверены как необходимая синхронизация с внешним миром.

## Правки после первого просмотра

По просьбе Игоря пробуем штатную тёмно-зелёную Phosphor вместо Paper, сохранив IBM Plex Mono. Палитра карты и вложенных Theme синхронизирована. Это эксперимент для следующего просмотра, не релиз в production.

- Вся карточка сценария — Link button на лендинге и Button в настройках. Описание, метки и свободная область входят в область нажатия, есть явная подпись «Выбрать». Метки используют Badge m.
- Активная навигация получила фон прикладной обёртки и текстовый маркер на десктопе, верхнюю линию на телефоне; aria-pressed сохранён.
- Настройки шириной 440px от 768px и 480px от 1024px. Список городов остаётся 400px, телефон — на всю ширину.
- Каждый фактор в Panel. В строке названия больше нет меняющего ширину веса. Отдельно подписаны «Важность: N из 10» и «Доля весов: N %»; пояснено, что это не оценка города и при пропусках веса перераспределяются.
- Общий балл крупнее, текстовые уровни Badge m; длинные подписи списка могут переноситься без наложения на число. Подсказкам в разборе города добавлены внешние отступы и выравнивание по центру.

### Подтверждённые ограничения UIKit 0.1.0

Проверены установленный `dist/theme.css`, Checkbox, Popover и Progress, а не предположения по скриншоту:

- Input использует `--bg`, совпадающий с фоном Theme, и имеет focus, но не отдельное hover-состояние. В панели приложения поле теперь визуально отделяется от поверхности Panel.
- Checkbox не имеет отдельного hover-состояния. Размеры/контраст его mark принадлежат библиотеке.
- Button и Progress имеют прозрачный фон. Смена Paper на Phosphor этого не меняет. Для Progress нет публичного prop фона дорожки.
- Минимальная кнопка Popover s — 36px (44px при coarse pointer). Для плотной строки метрик нет публичного inline/compact размера. Внутренний размер не уменьшали CSS-патчем.
- Badge m крупнее s, но по-прежнему текстовая метка без варианта заливки. Для крупной числовой оценки использована предметная композиция, а не копия Badge.
- Разница зелёного и жёлтого требует следующего визуального просмотра стандартной Phosphor. Подписи уровней сохраняются: смысл не кодируется одним цветом.

Внутренние селекторы/стили пакета не переопределялись, пакет не патчился. Issues не публиковались: обсуждаем предложения после следующего просмотра.

## Второй просмотр: данные и структура

Карта теперь использует независимую светлую картографическую палитру, а не Phosphor UI. Более тёмные маркеры отделяются от светлой подложки и сохраняют дополнительную обводку выбранного города. Таблица использует вложенный Theme через публичные colors: нейтральные числа, слабые заливки вместо яркого текста, приглушённые пунктирные линии. Общая тема интерфейса остаётся Phosphor.

Балл снова отображается штатным Badge m: крупное число находится в children, рамку/скобки рисует библиотека. Прикладные разделители списка и навигации стали пунктирными. Счётчик скрытых городов с кнопкой сброса вынесен за пределы прокрутки списка и оформлен Panel. Группы «Тянет вверх», «Тянет вниз» и «Остальное» разделены Panel с заголовками 20px и внешними интервалами 32px. Это исправления приложения, не дефекты UIKit.

Отчёт с отдельными черновиками issues: [обратная связь для UIKit](ascii-ui-issue-drafts.md). Публикации и релиза в main нет; изменения предназначены для повторного просмотра preview.
